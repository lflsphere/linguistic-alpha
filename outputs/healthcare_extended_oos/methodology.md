## Provenance and protected inputs

The evaluation reads `outputs/sp500_financial_extension/sp500_model_extended.csv`, the financial validation table and feature lineage in that directory, the previously validated CAR extension in `outputs/sp500_car_extension/`, and the saved original Healthcare run in `outputs/healthcare_original_pierre_replication/`. The frozen source revision is `06273f1766daeb29de4b9313dd20639439a09671`. The evaluation verifies archived source hashes for `experiments/pierre_original/`, the original model CSV hash and input row identities. The financial extension and CAR extension were checked through all 29,698 rows and all columns. Differences are allowed only for the 16 approved financial fields from 2025 onward. This preserves prior CARs, updated CARs, event IDs, security fields and archived linguistic fields. The financial reconstruction and market CAR extension are reused as saved.

`sector == 'Health Care'` selects the event universe, preserving the archive's static classification. Both benchmark cohorts are identical by event ID in all periods here. For new events the evaluation independently checks the exact CIQ transcript and dated security link through the previously verified mapping function, requires active CIZ S&P 500 membership on the call date, and requires a valid completed target. It verifies that the New York and archived UTC dates agree for the new Healthcare sample. There are 214 target-valid 2025 events and 107 target-valid 2026 events. Dated membership excludes three in each year. No target-valid event fails the linkage check. The 86 source 2026 events without a valid target lack a complete observable window at the local return cutoff. Missing predictors use the original imputation. No event is removed based on realized return magnitude, model scores or the later clock-gated timing screen.

## Benchmark and event windows

Day 0 uses the pinned `assign_day0` implementation. Convert the archived timestamp to New York time. Calls before 16:00 Eastern on a CRSP session map to that session. All other calls roll to the next CRSP session. A missing call time defaults to the first session strictly after the fallback date in the helper. Event offsets count sessions. Each target uses the arithmetic sum of stock return less the matched same-date benchmark return from +2 through +20, inclusive. Early CAR uses offsets −1 through +1. Market targets are the validated `car_2_20` values with `SPRTRN`, the S&P 500 price-return series. The market Early CAR is `car_-1_1` in the extended table. Original `car_0_1` and `AR01` do not enter either option.

Healthcare daily returns use the original static Compustat GICS 35 snapshot. The reconstruction fills the snapshot for firms outside the event export with the most recent available local Compustat GICS record, then collects linked securities from CCM. For the CIZ period the eligible basket includes links present in either local vintage. Each trading day includes its dated S&P 500 member securities. Among rows with a return and positive capitalization, compute the sum of `abs(price) × shares × return` divided by the sum of `abs(price) × shares`. The original uses same-day capitalization, so the benchmark is a research comparator with contemporaneous weights and static classifications. It is unsuitable as a claim about an executable portfolio. A sector return requires positive observed weight. Each extended event requires every session and both returns for the target, without zero-filling missing returns or reweighting the event window.

Legacy benchmark and event calculations use daily `RET`, without an extra `DLRET` splice in the sector extractor. From 2025, `dlyret` includes CIZ delisting effects. The script retains that return and does not add a second delisting return. It treats Early CAR as missing if a CIZ delisting flag appears in its window, with the frozen imputation available. The matched samples here have no missing Early CAR. The original historical extractor can truncate windows. The new target explicitly enforces full maturity through 2026-06-30. The sector return is written separately from the full-universe source table. No substitute ETF or benchmark is used.

The validation replays all 252 daily 2024 legacy sector benchmark observations, 205 Early CAR labels and 204 forward CAR labels. All match within the frozen 1e−10 return-unit gate. The newer CIZ overlapping 2024 feed is separately tested against the archived events. The frozen bridge requires complete matched counts, at least 95% of labels within 5 basis points and all within 25 basis points. The observed maximum errors are about 0.01052 bp for Early CAR and 0.02926 bp for forward CAR. Each gate passed before OOS fitting or scoring. The validation table reports errors in fractional return units. Multiply by 10,000 to obtain basis points.

## Frozen development fit and scoring

`frozen_experiment_spec.json` records the selected estimators, complete ordered feature lists, all resolved estimator parameters, coding hashes, periods, metric rules and bootstrap configuration. The script saves this manifest before sector extension and new OOS scoring. The archived estimator and strategy choices were recovered from `native_model_metrics.csv` and checked against the six-strategy archive. Refits use only the original 2,939 native development observations per benchmark (2010–2023, 95 issuers). Six replay tests reproduce all 204 saved 2024 scores per benchmark/model exactly. 2024 metrics use saved predictions on these events, including for quintiles, and 2024 remains a previously examined diagnostic because test performance informed the historical strategy and estimator choices.

A uses 16 original controls including Early CAR, historical call count and transcript structure. B adds the archived selected LM5 in its original order. B* adds all nine LM columns. The original dictionary makes `hedging_answers` and `uncertainty_answers` identical. The redundant inputs are kept. The supplied `prior_calls_with_target` is carried forward as archived and does not accrue OOS outcomes. No model includes the reconstructed post-event volatility field. The original preprocessing applies `log1p(max(x, 0))` to listed predictors, then clips to development 1st/99th percentiles, fills with the corresponding development median and applies development-fitted standard scaling. The model predicts unnormalized one-based average midranks of development CAR. S&P 500 A/B use Ridge α=1 and B* uses Ridge α=10. Healthcare A uses Ridge α=1, B uses Elastic Net α=0.05 and L1 ratio 0.7, and B* uses Ridge α=50.

An Early CAR value cannot be known until after the Day +1 close, immediately before the first target session. The original specification imposes no transcript delivery gate and no global financial-feature or execution availability gate. Upstream reconstruction checks specific financial data timing. That work does not establish that the entire feature vector was available at the call or by a particular trading decision. The target's first session return starts from the previous close, which is relevant to an executable entry assumption. The study estimates an event-level predictive association conditional on the data convention.

## Metrics and inference

- Rank IC is Spearman correlation with average ties. The incremental statistic is the difference in IC between the LM model and A on the same events. Pearson correlation is supplementary. Score ranking agreement is Spearman correlation between model scores. No return-scale calibration or directional threshold is fit, so continuous prediction errors, R² and directional hit rates are omitted.
- Each period and benchmark uses its own predicted-score quintiles and prespecified minima of 50 events and 20 issuers. Quantile cuts use `pandas.qcut` with duplicate edges dropped. If fewer than five groups remain, the sort is marked insufficient. Score ties are kept together. Groups report count, mean, median and sample SD of realized CAR. Spreads subtract Q1 mean from Q5 mean. Strict monotonicity requires all four consecutive mean changes in the same direction. Returns are event-level and the holding windows overlap. Aggregating them does not produce a portfolio NAV.
- The pooled analysis recomputes correlations and sorts over all eligible new events. Quarterly Rank IC requires at least 30 events and 15 issuers. A partial Q2 2026 result is displayed, then excluded from full-quarter rankings, SD and positive IC share. Those summaries require three full quarters. The unannualized ICIR requires six and is withheld because five qualify.
- Resampling uses shared event indices across A, B and B* and recomputes Rank IC inside each draw. Issuer-cluster resampling draws GVKEYs with replacement and keeps all calls associated with each draw. Calendar-time resampling uses overlapping noncircular two-calendar-month blocks in call-date order, including empty months. A block draw preserves the cross-sectional calls within each month. It approximates dependence from event clustering and overlapping return windows. The paired methods probe different dependence structures, and the number of blocks constrains precision. Neither interval estimates the full uncertainty of repeating the training process.
- Percentile 95% intervals require at least 30 issuers, five nominal disjoint two-month blocks and 95% valid replicates. Each eligible group uses 2,499 replicates per method. 2025 intervals are pointwise. Partial 2026 and the selected 2024 diagnostic are descriptive. Pooled centered two-sided bootstrap p-values include a +1 finite-draw correction. Use the larger of the two method-specific p-values per comparison and apply Holm across two models by two benchmarks. A pooled confirmatory result requires adjusted p≤0.05 and both intervals exclude zero in the same direction. Both variants' estimates fall below zero for both pooled benchmarks and all intervals cover zero.

## Reproduction and output map

Run from the repository root in PowerShell. The commit contains the scripts, frozen specification, aggregate validation and research tables, and aggregate HTML. The private inputs and derivatives remain local. The PDF is generated locally by the same renderer, consistent with the repository's use of tracked HTML reports.

1. Provide the approved `model_table_with_linguistic.csv` snapshot, the local `data/raw/` and `data/team_pit/sp500_pit/` inputs, and the Git object `06273f1`. Use the archived [replication instructions](../healthcare_original_pierre_replication/reproduction.md) through the original `model` step to regenerate missing local artifacts. This workflow needs only the original extraction and model stages. The later corrected comparison is separate. The evaluation expects the pinned sources in `experiments/pierre_original/` and the original artifact directory to contain `provenance.json`, `native_model_metrics.csv`, `original_test_predictions.parquet`, and `earnings_health/{model_table_opt1.parquet,model_table_opt2.parquet,health_sector_daily.parquet}`. Keep an existing historical run intact and use its authorized files when available.
2. Run [the CAR extension](../sp500_car_extension/methodology.md) into a fresh destination. Place the resulting local `sp500_car_extended.csv` at `outputs/sp500_car_extension/sp500_car_extended.csv` if it is absent. Then run [the financial reconstruction](../sp500_financial_extension/feature_lineage.md) into a fresh destination. Place its `sp500_model_extended.csv` at `outputs/sp500_financial_extension/sp500_model_extended.csv` if it is absent. Both commands reject existing output sets. Check the saved aggregate tables before using a regenerated dataset.
3. Run the evaluation into a fresh destination. The reporting script reads aggregate CSVs and the manifest alongside the script. To render from a fresh evaluation, copy `render_report.py` to that destination and execute it there.

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
$dest = 'outputs/healthcare_extended_oos/reproduction'
.\.venv\Scripts\python.exe outputs/healthcare_extended_oos/evaluate.py --out $dest
Copy-Item outputs/healthcare_extended_oos/render_report.py,outputs/healthcare_extended_oos/methodology.md $dest
python "$dest/render_report.py"
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_extended_research.py
```

Model runs used pandas 2.2.3, NumPy 2.5.4, SciPy 1.18.1, scikit-learn 1.9.1, and PyArrow 26.0.1. Rendering used Matplotlib 3.7.5. Modern raw input dependencies are in `data/team_pit/sp500_pit/` including `crsp_dsf_v2_2024.parquet`, `crsp_dsf_v2_2025.parquet`, `crsp_dsf_v2_2026.parquet`, `crsp_dsp500_v2.parquet`, `crsp_msp500list_v2.parquet`, CCM and CIQ mapping inputs. Legacy benchmark reconstruction uses `data/raw/crsp_dsf_2024.parquet`, `crsp_dsi.parquet`, `crsp_msp500list.parquet`, CCM and the latest local Compustat GICS snapshot. Archived option-specific training tables, predictions and the 2024 benchmark are read from the saved run.
